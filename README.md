# Raft.NET

**Raft.NET** — учебная реализация алгоритма распределённого консенсуса [Raft](https://raft.github.io/) на C# с использованием ASP.NET Core.

Проект посвящён изучению принципов построения распределённых систем, включая выбор лидера, репликацию журналов, обеспечение согласованности данных и отказоустойчивость.

Основная цель — реализовать распределённое Key-Value хранилище с нуля, последовательно изучая механизмы консенсуса, сетевого взаимодействия, конкурентного выполнения операций и восстановления после отказов.

## О проекте

Raft — алгоритм распределённого консенсуса, позволяющий нескольким независимым узлам поддерживать согласованное состояние системы даже при отказе части участников кластера.

Каждый узел представляет собой отдельный процесс, взаимодействующий с другими узлами посредством HTTP RPC. Для согласования операций используется принцип большинства голосов (кворум).

Проект охватывает следующие механизмы:

- **Выбор лидера (Leader Election)** — автоматическое определение ведущего узла с использованием случайных тайм-аутов и голосования.
- **Репликация журнала (Log Replication)** — согласованное распространение записей между узлами кластера.
- **Реплицируемый конечный автомат (Replicated State Machine)** — детерминированное применение подтверждённых команд на каждом узле.
- **Распределённое Key-Value хранилище** — хранение и изменение данных с использованием алгоритма Raft.
- **Атомарные операции (CAS)** — условное обновление значений с помощью механизма Compare-and-Swap.
- **Распределённые блокировки (Distributed Locks)** — координация конкурентного доступа клиентов к общим ресурсам.
- **Отказоустойчивость (Fault Tolerance)** — обнаружение отказов узлов, повторные выборы лидера и восстановление работы кластера.

## Архитектура

Система представляет собой кластер независимых узлов с динамически выбираемым лидером.

Каждый узел может находиться в одном из трёх состояний:

| Состояние | Описание |
|---|---|
| **Follower** | Принимает сообщения лидера и участвует в голосовании. |
| **Candidate** | Инициирует выборы при отсутствии действующего лидера. |
| **Leader** | Координирует работу кластера, принимает клиентские команды и управляет репликацией журнала. |

Взаимодействие между узлами осуществляется с помощью RPC-механизмов Raft, включая `RequestVote` и `AppendEntries`.

Архитектура предусматривает разделение логики консенсуса, сетевого взаимодействия, хранения состояния и клиентского API. Такой подход позволяет независимо тестировать компоненты системы и постепенно расширять её функциональность.

## Технологии

- **Язык программирования:** C#
- **Платформа:** .NET 10
- **Фреймворк:** ASP.NET Core
- **Сетевое взаимодействие:** HTTP / REST API
- **Асинхронность:** Async/Await, Background Services
- **Архитектура:** Распределённые системы, Replicated State Machine
- **Алгоритм консенсуса:** Raft

## Разработка

Проект разрабатывается поэтапно: от базового кластера с выбором лидера до распределённого хранилища с поддержкой атомарных операций и блокировок.

Первоначальная реализация сосредоточена на управлении состояниями узлов, голосовании, обнаружении отказов и повторных выборах лидера.

Последующие этапы предусматривают репликацию журнала команд, реализацию Key-Value хранилища и механизмов координации конкурентных операций.

Особое внимание уделяется корректности алгоритма, обработке сетевых ошибок, конкурентному выполнению запросов и сохранению согласованности при изменении состава доступных узлов.

Проект предназначен для образовательных и исследовательских целей и не позиционируется как готовое промышленное решение.
